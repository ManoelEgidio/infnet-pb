1. Visão Geral da Etapa (TP2)

Nesta segunda etapa do Projeto de Bloco, evoluímos a aplicação monolítica desenvolvendo uma camada de persistência real e robusta com o Spring Data JPA e Hibernate. A arquitetura foi estruturada para garantir alto desempenho, integridade relacional, isolamento de domínio e um mecanismo completo de auditoria e histórico de modificações de dados.

Destaques da Implementação:
  • Mapeamento Objeto-Relacional (ORM) completo com entidades Task, Category e TaskHistory.
  • Relacionamentos @ManyToOne e @OneToMany com índices otimizados (@Index).
  • Trilha de Auditoria imutável (TaskHistory) registrando criação, alterações de status, mudanças de prioridade, valores anteriores e novos, autor e timestamp.
  • Consultas JPQL customizadas (@Query), métodos derivados e paginação (Pageable).
  • Suíte de testes automatizados com perfis isolados (@SpringBootTest, @ActiveProfiles("test") e transações atômicas).
  • Interface Frontend moderna em React integrada com timeline interativa de histórico de auditoria.

2. Modelagem de Dados e Mapeamento JPA

A estrutura relacional foi modelada para suportar alta escalabilidade, isolamento de responsabilidades e controle transacional:

+--------------------+ +--------------------+ +------------------------+ | tb_categories | 1 * | tb_tasks | 1 * | tb_task_history | +--------------------+------------+--------------------+------------+------------------------+ | id (PK) | | id (PK) | | id (PK) | | name (UNIQUE) | | title (VARCHAR) | | task_id (FK/Index) | | description | | description | | action_type (ENUM) | | color_code | | priority (ENUM) | | field_changed (VARCHAR)| | created_at | | status (ENUM) | | old_value (VARCHAR) | +--------------------+ | category_id (FK) | | new_value (VARCHAR) | | created_at | | details (VARCHAR) | | updated_at | | changed_by (VARCHAR) | | due_date | | changed_at (TIMESTAMP) | +--------------------+ +------------------------+

Anotações JPA Aplicadas na Entidade Task:

@Entity @Table(name = "tb_tasks", indexes = { @Index(name = "idx_task_status", columnList = "status"), @Index(name = "idx_task_priority", columnList = "priority"), @Index(name = "idx_task_category", columnList = "category_id") }) public class Task { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Embedded @AttributeOverride(name = "value", column = @Column(name = "title", nullable = false, length = 100)) private TaskTitle title; @Enumerated(EnumType.STRING) @Column(name = "priority", nullable = false, length = 20) private Priority priority; @Enumerated(EnumType.STRING) @Column(name = "status", nullable = false, length = 20) private TaskStatus status; @ManyToOne(fetch = FetchType.EAGER) @JoinColumn(name = "category_id") private Category category; // timestamps e métodos de domínio }

3. Histórico de Mudanças e Auditoria de Dados (Data History)

Para atender ao requisito de auditoria e rastreabilidade corporativa, foi criada a entidade TaskHistory e o serviço transacional TaskHistoryService. Sempre que uma tarefa é criada, tem seu status alterado ou passa por edição de detalhes, uma entrada imutável de log é persistida contendo:

  • Tipo de Ação: CREATED, STATUS_CHANGED, DETAILS_UPDATED, PRIORITY_CHANGED, DELETED.
  • Valores: Registro do valor anterior (old_value) e do novo valor (new_value).
  • Metadados: Autor responsável (changed_by) e data/hora exata (changed_at).
@Entity @Table(name = "tb_task_history", indexes = { @Index(name = "idx_history_task_id", columnList = "task_id"), @Index(name = "idx_history_changed_at", columnList = "changed_at") }) public class TaskHistory { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(name = "task_id", nullable = false) private Long taskId; @Enumerated(EnumType.STRING) private ActionType actionType; private String fieldChanged; private String oldValue; private String newValue; private String details; private String changedBy; private LocalDateTime changedAt; }

4. Repositórios Spring Data e Consultas Otimizadas

Os repositórios aproveitam o poder do Spring Data com consultas derivadas e consultas customizadas via JPQL:

@Repository public interface TaskRepository extends JpaRepository { @Query("SELECT t FROM Task t WHERE " + "(:status IS NULL OR t.status = :status) AND " + "(:priority IS NULL OR t.priority = :priority) AND " + "(:categoryId IS NULL OR t.category.id = :categoryId)") List findByFilters( @Param("status") TaskStatus status, @Param("priority") Priority priority, @Param("categoryId") Long categoryId); @Query("SELECT t FROM Task t WHERE " + "(:status IS NULL OR t.status = :status) AND " + "(:priority IS NULL OR t.priority = :priority) AND " + "(:categoryId IS NULL OR t.category.id = :categoryId)") Page findByFiltersPaged( @Param("status") TaskStatus status, @Param("priority") Priority priority, @Param("categoryId") Long categoryId, Pageable pageable); @Query("SELECT t FROM Task t WHERE t.dueDate IS NOT NULL AND t.dueDate < :now AND t.status <> 'COMPLETED'") List findOverdueTasks(@Param("now") LocalDateTime now); }

5. Testes Automatizados da Camada de Persistência

A suíte de testes automatizados valida o comportamento dos repositórios, a consistência dos dados, as queries customizadas e o fluxo de auditoria sob isolamento transacional:

// Exemplo de Teste Automatizado de Repositório e Auditoria @SpringBootTest @ActiveProfiles("test") @Transactional class TaskHistoryRepositoryTest { @Autowired private TaskHistoryRepository historyRepository; @Test @DisplayName("Deve registrar e consultar histórico de alterações ordenado cronologicamente") void testSaveAndFindHistory() { TaskHistory h1 = new TaskHistory(100L, ActionType.CREATED, "TASK", null, "Nova Tarefa", "Criação", "Manoel"); TaskHistory h2 = new TaskHistory(100L, ActionType.STATUS_CHANGED, "status", "PENDING", "IN_PROGRESS", "Início", "Manoel"); historyRepository.save(h1); historyRepository.save(h2); List list = historyRepository.findByTaskIdOrderByChangedAtDesc(100L); assertEquals(2, list.size()); assertEquals(2, historyRepository.countByTaskId(100L)); } }
