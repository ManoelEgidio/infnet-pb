1. Contexto e Objetivo da Etapa (TP3)

No escopo do curso de Engenharia de Softwares Escaláveis, a terceira etapa envolve a transição e expansão da aplicação monolítica anterior para uma arquitetura distribuída baseada em microsserviços.

O objetivo central foi desacoplar as responsabilidades de comunicação, eventos e entrega de alertas, criando um novo microsserviço autônomo (notification-service) construído com Spring Boot e integrado ao serviço central de tarefas (task-service) por meio de comunicação declarativa distribuída com Spring Cloud OpenFeign, aplicando os padrões de Database-per-Service, Bounded Context e Graceful Degradation / Fallback.

2. Arquitetura do Sistema Distribuído

A solução foi estruturada em dois serviços de backend independentes e uma camada de apresentação front-end moderna e reativa:

2.1. Princípios Arquiteturais Aplicados

  • Separação de Responsabilidades (SRP / Bounded Contexts): O ciclo de vida da tarefa reside exclusivamente no task-service, enquanto as regras de alerta, canais (IN_APP, EMAIL, WEBHOOK), status de leitura e histórico de destinatários residem no notification-service.
  • Database-per-Service: Cada microsserviço possui seu próprio banco de dados isolado (taskdb e notificationdb), impedindo acoplamento de tabelas ou joins entre serviços distintos.
  • Comunicação Declarativa com Spring Cloud OpenFeign: A comunicação síncrona HTTP entre os serviços é realizada através de interfaces tipadas com anotações Spring MVC, eliminando boilerplate de HTTP clients.
  • Resiliência e Tolerância a Falhas (Fallback Pattern): Caso o notification-service esteja temporariamente indisponível ou lento, o NotificationClientFallback no task-service absorve a falha, registrando log de contingência sem interromper o fluxo principal de tarefas do usuário.

3. Atualização do Modelo de Domínio

3.1. Modelo do Microsserviço de Notificações (notification-service)

Foi modelada a entidade de domínio Notification contendo os seguintes atributos, índices e Value Objects:

@Entity @Table(name = "notifications", indexes = { @Index(name = "idx_notifications_recipient", columnList = "recipient"), @Index(name = "idx_notifications_is_read", columnList = "is_read"), @Index(name = "idx_notifications_task_id", columnList = "task_id"), @Index(name = "idx_notifications_created_at", columnList = "created_at") }) public class Notification { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; private Long taskId; private String taskTitle; private String recipient; private String message; @Enumerated(EnumType.STRING) private NotificationType type; // TASK_CREATED, STATUS_CHANGED, HIGH_PRIORITY_ALERT, etc. @Enumerated(EnumType.STRING) private NotificationChannel channel; // IN_APP, EMAIL, WEBHOOK private boolean isRead; private LocalDateTime createdAt; private LocalDateTime readAt; // Métodos de negócio: markAsRead(), etc. }

3.2. Atualização do Modelo no Serviço Principal (task-service)

O serviço principal incorporou o cliente distribuído NotificationClient diretamente na execução de suas operações de negócio (createTask, updateTask, updateTaskStatus e deleteTask).

@FeignClient( name = "notification-service", url = "${notification.service.url:http://localhost:8082}", fallback = NotificationClientFallback.class ) public interface NotificationClient { @PostMapping("/api/notifications") NotificationResponseClientDTO sendNotification(@RequestBody NotificationPayloadDTO request); @GetMapping("/api/notifications/task/{taskId}") List<NotificationResponseClientDTO> getNotificationsByTaskId(@PathVariable("taskId") Long taskId); }

4.2. Novo Endpoint Distribuído no Serviço Principal (task-service :8080)

Para demonstrar a comunicação transparente entre serviços, foi adicionado um endpoint que consulta o microsserviço de notificações via OpenFeign a partir da entidade de tarefa:

// GET http://localhost:8080/api/tasks/{id}/notifications @GetMapping("/{id}/notifications") public ResponseEntity<List<NotificationResponseClientDTO>> getTaskNotifications(@PathVariable Long id) { List<NotificationResponseClientDTO> notifications = taskService.getTaskNotifications(id); return ResponseEntity.ok(notifications); }

5. Repositório de Dados Dedicado (Database-per-Service)

No microsserviço notification-service, foi criado o repositório Spring Data JPA NotificationRepository, que opera exclusivamente sobre o banco de dados dedicado notificationdb:

@Repository public interface NotificationRepository extends JpaRepository<Notification, Long> { List<Notification> findAllByOrderByCreatedAtDesc(); List<Notification> findByRecipientOrderByCreatedAtDesc(String recipient); List<Notification> findByIsReadFalseOrderByCreatedAtDesc(); List<Notification> findByRecipientAndIsReadFalseOrderByCreatedAtDesc(String recipient); List<Notification> findByTaskIdOrderByCreatedAtDesc(Long taskId); long countByIsReadFalse(); long countByRecipientAndIsReadFalse(String recipient); @Modifying @Query("UPDATE Notification n SET n.isRead = true, n.readAt = CURRENT_TIMESTAMP WHERE n.recipient = :recipient AND n.isRead = false") int markAllAsReadByRecipient(@Param("recipient") String recipient); @Modifying @Query("UPDATE Notification n SET n.isRead = true, n.readAt = CURRENT_TIMESTAMP WHERE n.isRead = false") int markAllAsRead(); }

6. Componentes Front-End Desenvolvidos

A interface de usuário em React foi ampliada com componentes visuais dedicados à interação com o microsserviço:

  • Central de Notificações (NotificationCenter.jsx): Painel deslizante com efeito glassmorphism contendo contadores, filtros por lidas/não lidas/alertas, botões de ação em lote ("Marcar todas como lidas") e emissor de mensagens broadcast em tempo real.
  • Sino de Notificações com Badge Reativo (Navbar.jsx): Exibe o contador de alertas não lidos em tempo real com animação de pulso luminoso (ping effect) quando chegam novos eventos.
  • Monitor de Saúde dos Microsserviços (ServiceStatusIndicator.jsx): Exibe no cabeçalho o status de conectividade em tempo real dos serviços (task-service :8080 [Online] e notification-service :8082 [Online]).
  • Alertas Toast em Tempo Real (NotificationToast.jsx): Notificações flutuantes que surgem instantaneamente quando ações de tarefas emitem eventos ao microsserviço.
  • Modal de Notificações por Tarefa (TaskNotificationModal.jsx): Botão de sino em cada cartão Kanban permitindo inspecionar a rota distribuída de alertas associados àquela tarefa.
