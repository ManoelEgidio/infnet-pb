1. Visão Geral da Solução

A solução desenvolvida para o TP1 consiste em uma aplicação monolítica de gestão de tarefas (Task Management System). O sistema serve de base para futuras evoluções em direção a uma arquitetura de microsserviços nos próximos Trabalhos Práticos.

2. Estrutura em Camadas (Layered Architecture)

O back-end foi estruturado em quatro camadas principais:

  • Controller Layer: TaskController gerencia requisições HTTP REST e retornos serializados em JSON.
  • Service Layer: TaskServiceImpl orquestra as regras de negócio e validações do sistema.
  • Domain Layer: Entidade JPA Task, Value Object TaskTitle e Enums Priority / TaskStatus.
  • Repository Layer: TaskRepository estende JpaRepository para persistência no H2 In-Memory Database.

3. Autoconfiguração e SOLID

A autoconfiguração do Spring Boot foi utilizada via spring-boot-starter-web e spring-boot-starter-data-jpa. Todos os princípios SOLID foram respeitados:

  • SRP: Separação estrita de responsabilidades por pacote (controller, service, repository, dto).
  • OCP: Extensibilidade via GlobalExceptionHandler.
  • LSP & DIP: Uso de interfaces para o serviço (TaskService) desacoplando instâncias concretas.
  • ISP: DTOs dedicados para request, response e métricas do dashboard.

4. Front-End em React

A interface do usuário foi construída com React e Vite, consumindo a API REST assincronamente através de um cliente HTTP em JavaScript. A interface fornece um painel com métricas em tempo real, criação e edição de tarefas, filtros por status/prioridade e notificações visuais.
